실습 1 · 90분

AI 코딩 에이전트로 웹앱 만들기 — 장비 점검 체크리스트

요구사항 7개(템플릿 선택, 이상 시 메모 필수, 저장·필터, CSV 내보내기, 오프라인, 모바일)를 표로 주고 Claude Code가 단일 HTML 앱을 만들게 합니다. 완료 기준은 사람이 직접 하나씩 확인합니다.

  1. 요구사항 표를 붙여 넣고 "계획부터 보여줘"
  2. 계획을 고친 뒤 구현 요청 → 브라우저에서 R1~R7 확인
  3. 실패 항목은 "재현 방법 + 기대 결과"로 다시 지시
  4. git init 후 "AI 에이전트 작성, 사람 검증" 커밋
참고 답안 실행해 보기요구사항·지시 예시
실습 2 · 90분

테스트 주도로 업무 도구 만들기 — 정비 이력 분석기

함수 뼈대와 실패하는 테스트 8개가 주어집니다. 에이전트에게 "테스트는 고치지 말고 구현만"을 지시하고, 통과하면 기능 추가를 테스트부터 요청합니다.

cd practice\lab2-maintenance
pytest -q              # 처음엔 모두 실패
claude                 # "tests를 읽고 maintenance.py만 구현해 모두 통과시켜라"
pytest -q              # 8 passed
python maintenance.py  # 정비 현황 보고서 출력

관찰 포인트: 에이전트가 테스트를 고치거나 답을 하드코딩하려 하는가? 사람이 diff를 읽어야 하는 이유입니다.

실습 3 · 90분

GitHub로 협업하고 배포하기

이슈 → 브랜치 → 초안 PR → 자동 테스트(GitHub Actions) → 동료 검토 → 병합 → GitHub Pages 배포까지 전 과정을 직접, 그리고 GitHub 에이전트로 한 번 더 해 봅니다.

gh issue create --title "이상 항목 사진 첨부"
git switch -c feature/photo
...
gh pr create --draft
python agent-labs\lab2_github_agent.py --repo . "열린 이슈와 PR, Actions 결과를 점검해라"

처음 로그인한 gh 토큰에는 workflow 권한이 없어 Actions 파일 푸시가 거부됩니다. 오류를 읽고 gh auth refresh -s workflow로 해결하는 과정도 실습의 일부입니다.

요구사항·참고 답안
종합 과제 · 팀 3~4명

우리 부서의 반복 업무 하나를 앱으로

  1. 문제 고르기: 매주 30분 이상 걸리는 반복 업무 (예: 근무표 작성, 교육 출석 집계, 물품 대여 대장)
  2. 요구사항 표: 번호·요구사항·완료 기준. 실제 자료 대신 가상 데이터 설계
  3. 개발: 에이전트로 구현, 테스트 최소 5개
  4. 협업: 기능마다 이슈·브랜치·PR, 팀원 1명 이상 리뷰, Actions 통과
  5. 발표 (10분): 시연, 절약되는 시간, 에이전트가 틀렸던 사례와 잡아낸 방법, 업무망 적용 시 필요한 승인
